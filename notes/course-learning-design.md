# Learning progression across the course

## Decision and authorisation

The reader approved the anatomy/nested-data pilots and requested the same treatment for the
whole course, explicitly removing the combined chapter pages. The course now has sixteen module
indexes and fifty-six core lessons. Optional build labs retain code and exercises. Bounded
notes, further practice and comparison pages retain supporting material. No combined chapter is
published. Old chapter URLs are module indexes, old section links route to their content owner,
and the two pilot index URLs redirect.

Canonical chapter Markdown remains the authoring source. It keeps the seven-section structure
for parsing and checks, while the published lesson boundaries follow observable outcomes.
All literal and generated includes have exactly one published owner. No duplicate prose or code
is maintained for a second presentation.

## Learning-design brief

Applied Assembly Lab’s learning-design skill at
https://github.com/snowch/assembly-lab/blob/c52703d58e14f2783e7cb785ff1e757ba36ccd42/.agents/skills/learning-design/SKILL.md.

`tools/lessons.py` records each lesson’s observable outcome and preparation. The core route
defines and demonstrates a mechanism before a fresh application with specific reasoning.
Code, implementation labs and further practice remain optional. The lesson’s essential
qualifications stay on its visible route, rather than only in supplemental notes.

The sequence separates naming, demonstrating and practising a mechanism. Important changes:

- Schema paths precede type interpretation and maximum-level counting. Optional fields on the
  path include the leaf; a binary schema-damage investigation moves to the build lab.
- Dictionary values, integer differences, string prefixes and byte positions get separate
  lessons. A tiny complete integer sequence precedes blocks; raw delta headers and zigzag
  belong to the optional implementation path.
- Walking pages, comparing versions and diagnosing checksums are separate outcomes. Page-size
  policy stays available as supporting material and later writer guidance.
- Compression begins with a complete overlapping copy before codec framing and the full byte
  inspector. The native copy routine computes the schematic output. Comparisons distinguish
  patterns, sizes and unmeasured runtime costs.
- Statistics teach typed order before usable bounds and the reader’s report. Missing
  statistics, proven all-null chunks and exceptional floats are separate decisions.
- Skipping teaches row groups, cross-column row ranges and Bloom filters before their combined
  comparison. A small unequal-boundary worked case precedes the fresh overlap task.
- The complete dependent scan and controlled writer comparison remain intact. They are useful
  investigations, not one page per request or knob.
- Query scanning, metadata-only answers, dictionary grouping, sorted limits and join-derived
  filters have distinct outcomes. A two-dictionary miniature demonstrates local identity before
  the fresh grouping case. The join figure remains explicitly a scan, not an executed join.
- Encryption separates footer visibility, key references and module inspection. The keyless
  inspector’s inability to decrypt or authenticate remains visible.
- Table membership gets a complete add/remove history before the fresh case. Snapshot/delete
  meaning is demonstrated before the named history, lookup, update-cost and compaction lessons.
- Iceberg’s metadata, field identity, partition evolution and commits are separate. Repeated
  feature-map/comparison context moves out of the core route. Metadata-tree and concurrency
  explanations remain explicitly schematic, not claims about an executed implementation.

Misconception evidence is the explanation or reconstruction requested by each fresh task:
recognition versus validation, bounds versus presence, local versus global indices, value
counts versus rows, stored bytes versus decompressed sizes, and membership versus physical
presence. A reveal click or reading-position record does not establish learning.

## Independent review decisions

Separate early-course and late-course learner reviews covered every resulting core lesson.
A separate technical review checked ownership, routing, deep links, native cases and limits.
Reviewers used independent sessions of the available inherited model; this was not a model
comparison or a novice study.

Accepted corrections included local schema/bit-packing bridges, a complete RLE example, fresh
page-overlap and dictionary-identity examples, the UTC/non-zero timestamp premise, a safe-bounds
qualification for top-k scanning, stale above/below references, and field-on-path terminology.
Binary mutation moved off the core schema-counting route. Library confirmation of the scan
stayed with that scan; it did not become an unrelated join example.

The concern that V2 lacked a no-code demonstration was rejected after checking the saved V2
comparison. A large inspector’s DOM token count alone was also rejected as a reason to split:
byte maps, token controls and internal scrolling are not an equivalent prose reading load.

Old saved chapter scroll offsets are reset to the module choices; individual lesson positions
still resume. Native fallback anchors identify the correct module entry when JavaScript is off.

## Checks and evidence limits

Independent browser review covered all core lessons at phone/dark and desktop/light, with
reverse-theme samples and inspected phone screenshots. It checked discoverability, closed code,
fresh cases, keyboard feedback and reflow. Essential no-JavaScript routes were checked broadly;
the automated suite checks every core lesson with JavaScript off in both viewports/themes.

Component worker/lab regression tests use explicitly private harnesses outside the publish
directory. They are never linked, deployed or offline-cached. Separate public-course browser
tests visit every actual core lesson and module, execute a real walkthrough in every module,
and check deep links, aliases and resume. Source ownership checks include generated evidence as
well as quoted code. These checks have different jobs and must not be conflated.

The complete `make check` passed: Rust formatting/lints/tests, fixture and figure reproducibility,
saved-output freshness, generated-number checks, strict parsing, all built links, all 761 Python
tests and the complete browser suite. The 43 unsolved exercise tests remain intentionally skipped.
The browser suite executed a retained walkthrough on a real lesson page in every module and
checked all core reading routes without JavaScript. Its grouped-menu and dual-storage legacy
resume cases also passed. Regression assertions were updated for the private harness query
string, closed native sidebar groups and the menu’s supported button/Back controls.

There has been no novice study, assistive-
technology study or complete accessibility audit. Predictions about learner difficulties and
the proposed boundaries remain hypotheses. Next evidence is a new reader attempting unfamiliar
cases without coaching, recording first attempts and help separately. The reader authorised
course-wide rollout without waiting for that study; no learning-effectiveness certification is
claimed.
